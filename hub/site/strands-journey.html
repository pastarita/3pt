Strands, answered

Four questions asked of the basis we build on, each answered in a breath and pinned to the docs, the code, and Strands itself. The pointers are the page.

station 1How can we configure Strands?

Three layers, one document. The harness options (createHarness), the model and its router (ModelRouter), and the agent passthrough (AgentConfig) are all plain data. A 3PT Policy compiles into them in harnessOptions(), grants() and routerSpec(). Try a shape by hand in the strands CLI first, then /export and diff.

station 2How can we fine-tune Strands?

Not the weights. Strands has no seam for weight fine-tuning, and the guide gives no AWS credits. It tunes the harness configuration instead: a Formula exposes tunable parameters, evals produce the reward, Trainer.fit() steps. Below that sit dials with no training: effort, steering, classifier routing. Ours is a PolicyFormula rewarded by M-19.

station 3How is Strands open to self-improvement?

Strands does not improve itself; it exposes the seams. Hooks see every call, the harness is data, Storage and snapshots remember, checkpoints pause and roll back, memory stores carry, the optimizer trains, a Graph run stays inspectable. 3PT closes the edge: rewritePolicy() writes the next policy, and a checkpoint is a triple.

station 4How does the 3PT workflow look for media-heavy content?

The loop runs on the right side; the media is the left. Plan reads the media state. Build, a Strands harness with the media tools granted, edits the pipelines; the worker drains the jobs. Instrument reads M-5 to M-10 and rewrites the context policy, and the migrations follow.
